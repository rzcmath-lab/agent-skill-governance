# Privacy Boundary

Public skill documentation must stand on its own without exposing its private origin.

Remove or abstract:

- organization, product, repository, service, and team names;
- usernames, emails, machine names, absolute paths, and ticket identifiers;
- logs, prompts, payloads, database or API details, and operational thresholds;
- credentials, tokens, keys, endpoints, and configuration values;
- distinctive internal terminology that can reveal the source system.

Do not publish a renamed copy of private material. Rewrite the principle from first principles, then test whether every claim remains supported after its private context is removed. If not, omit it.
